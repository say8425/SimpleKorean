## 만든 방법

정책마다 `base-rule-block.md`에서 답변 문단 두 개만 `policies.json`의 문장으로 바꿨다. 나머지 문장은 모든 정책에서 같다. `permit`의 블록은 PR #10이 최종으로 넣은 규칙 블록과 같다. 조건은 다섯 가지다:

- `baseline`: 규칙 블록 없음
- `prohibit`: 서술형만 쓰게 하고 헤더와 목록을 막음
- `permit`: 헤더와 목록을 써도 되고, 쓸지는 모델이 정함
- `mandate`: 주제가 둘 이상이고 세 문단 이상인 답은 헤더로 나누게 함
- `permit_plus`: `permit`에 원인과 결과를 문장으로 잇게 하는 문장을 더함

답은 `claude-sonnet-5-5`가 effort low로 썼다. `evals/bench_common.py`의 격리 실행(`claude -p`, 사용자 설정과 MCP 서버 없음)을 썼다. 질문마다 두 번 답하게 했다.

## 판정

판정은 같은 질문, 같은 회차의 두 답을 비교했다. 판정 기록의 `pair`는 [앞 조건, 뒤 조건]이다. 첫 순서(`order1`)는 앞 조건의 답을 A로, 둘째 순서(`order2`)는 뒤 조건의 답을 A로 보였다. 기준은 세 가지다:

- `understand`: 분야를 잘 모르는 독자가 한 번 읽고 내용과 이유를 정확히 이해하기 쉬운 답
- `find`: 나중에 다시 볼 때 원인, 할 일, 명령을 빨리 찾을 수 있는 답
- `overall`: 질문한 사람이 받고 싶은 답

두 판정 모델 모두 순서마다 A, B, tie 가운데 하나를 골랐다. 두 순서에서 같은 조건을 고르면 그 조건이 이긴다. 두 순서의 선택이 다르거나 한쪽이 tie면 무승부(`tie`)다. `winner`는 이 규칙으로 정한 결과다.

Opus는 `judge-prompts.json`의 한국어 판정 문장으로 JSON 답을 냈다. `order1`과 `order2`에 순서마다 고른 답과 이유(`reason`)가 있다. Jev에게는 같은 기준을 영어 Choice 질문 세 개로 물었다. 선택지는 A, B, tie 세 개다. `order1`과 `order2`에 순서마다 고른 선택지와 세 선택지의 확률이 있다.

`p_x`는 앞 조건의 선택지에 Jev가 준 확률을 두 순서에서 평균한 값이다. tie에도 확률이 가므로 `p_x`가 0.5 이하여도 앞 조건이 이길 수 있다. 승패는 Jev가 돌려준 `choice`로 정했다. 확률은 소수 둘째 자리로 반올림되어 있다. 그래서 768번의 선택 가운데 4번은 `choice`의 확률이 가장 큰 확률보다 조금 작다. 그 가운데 1번은 부동소수점 오차로 생긴 차이다.

## 분석에 쓴 정의

- 목록 항목: 코드 블록 밖에서 `-`, `*`, `+`, 숫자와 마침표로 시작하는 줄이다. 코드만 있는 항목은 조각 항목의 분자와 분모에서 모두 뺀다.
- 조각 항목: 인라인 코드, 항목 끝의 "예:"나 쌍점, 끝에 붙은 괄호 덧붙임, 끝 부호를 뗀 뒤 "다", "까", "죠", "요"로 끝나지 않는 항목이다. "필요", "개요" 같은 명사와 명사형 끝("-함", "-음" 등)으로 끝나도 조각으로 센다.
- 연결어: "그러므로", "때문", "그래서", "따라서", "하지만", "그러나", "그러면", "므로", "반면", "대신"이 겹치지 않게 나온 횟수다. 코드 블록은 세지 않는다.
- 답변 결함과 문장 수: `evals/ko_lint.py`의 `reader_check`로 셌다.
- 길이 통제: 두 답의 글자 수 차이가 긴 쪽의 20% 미만인 쌍만 따로 셌다.
- 글자 수 중앙값: 답이 짝수 개라 가운데 두 값의 평균이다. 소수점은 반올림하지 않고 그대로 적는다.

넣지 않은 것은 Jev 응답 캐시와 판정 모델의 원래 출력 전문이다. 판정 결과는 판정 기록에 모두 들어 있다.
