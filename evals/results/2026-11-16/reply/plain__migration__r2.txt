백필(backfill)은 이미 있는 행에 새 칼럼 값을 채우는 작업입니다. 20GB 테이블에 NOT NULL 칼럼을 한 번에 추가하면 모든 행에 값이 필요해서 테이블 전체를 다시 쓰고, 그동안 락(lock)이 읽기와 쓰기를 막습니다. DBA는 이 작업을 여러 단계로 나누자는 뜻입니다.

DB 종류와 버전을 알려 주지 않았기 때문에 아래는 일반 절차입니다. 세부 명령은 엔진마다 다릅니다.

## 먼저 할 일

1. 멈춘 마이그레이션 세션을 취소하세요. 락이 풀려야 서비스가 회복됩니다.
2. 오래 열린 트랜잭션이 있는지 확인하세요. 이런 트랜잭션 뒤에서 ALTER가 락을 기다리면 다른 쿼리도 줄줄이 막힙니다.

## 단계별 절차

1. 칼럼을 NULL 허용으로, 기본값 없이 추가하세요. 이 작업은 대부분 바로 끝납니다.
2. 애플리케이션이 새 행에 값을 쓰도록 배포하세요.
3. 기존 행을 배치(batch, 일정 개수씩 묶은 단위)로 채우세요. 예를 들어 기본 키 범위로 1만 행씩 UPDATE하고, 배치 사이에 잠시 쉬세요. 큰 UPDATE 하나로 처리하면 같은 락 문제가 다시 생깁니다.
4. `WHERE col IS NULL`이 0건인지 확인하세요.
5. NOT NULL 제약을 거세요.

## 엔진별 참고

PostgreSQL이면 5단계를 락이 짧은 방식으로 할 수 있습니다.

- `ALTER TABLE t ADD CONSTRAINT c CHECK (col IS NOT NULL) NOT VALID;`
- `ALTER TABLE t VALIDATE CONSTRAINT c;` 이 명령은 쓰기를 막지 않습니다.
- `ALTER TABLE t ALTER COLUMN col SET NOT NULL;` 버전 12 이상에서는 검증된 CHECK가 있으면 전체 스캔을 건너뜁니다.

기본값이 상수이면 버전 11 이상에서는 `ADD COLUMN ... NOT NULL DEFAULT 값`이 테이블을 다시 쓰지 않습니다. 이 경우 백필이 필요 없을 수 있습니다.

MySQL이면 8.0 이상에서 `ALGORITHM=INSTANT`가 되는지 먼저 확인하세요. 안 되면 gh-ost나 pt-online-schema-change 같은 온라인 스키마 변경 도구를 쓰세요.

DB 엔진과 버전, 채울 값의 출처(상수인지, 다른 칼럼에서 계산하는지)를 알려 주시면 실제 명령과 배치 스크립트를 맞춰 드릴 수 있습니다.
