백필(backfill)은 이미 있는 행에 새 컬럼의 값을 채우는 작업입니다. NOT NULL 컬럼은 모든 행에 값이 있어야 하기 때문에, 한 번에 추가하면 DB가 20GB 전체를 처리합니다. 그동안 테이블 락(다른 세션의 접근을 막는 장치)을 잡기 때문에 읽기와 쓰기가 같이 막혔습니다.

DBMS와 버전을 알려 주지 않으셨기 때문에, 아래는 PostgreSQL 12 이상을 가정합니다. MySQL이면 3단계와 5단계가 다릅니다.

## 지금 할 일

1. 멈춘 마이그레이션 세션을 취소하세요. 취소하면 락이 풀리고 서비스가 돌아옵니다.
2. 같은 마이그레이션을 다시 배포하지 마세요. 같은 락이 다시 걸립니다.

## 다시 적용하는 순서

1. 기본값 없는 nullable 컬럼을 추가하세요. 메타데이터만 바꾸기 때문에 바로 끝납니다.
2. 애플리케이션이 새 행에 값을 쓰도록 배포하세요. 이 단계가 없으면 백필 중에 NULL 행이 계속 생깁니다.
3. 기존 행을 배치(batch, 행을 나눈 묶음)로 백필하세요. 한 배치는 1천~1만 행이 적당합니다. 배치마다 커밋하고 짧게 쉬세요.
4. 백필이 끝나면 NULL 행이 0개인지 확인하세요.
5. NOT NULL을 안전하게 거세요. 아래 순서를 따르세요.

```sql
ALTER TABLE t ADD CONSTRAINT t_col_nn CHECK (col IS NOT NULL) NOT VALID;
ALTER TABLE t VALIDATE CONSTRAINT t_col_nn;
ALTER TABLE t ALTER COLUMN col SET NOT NULL;
ALTER TABLE t DROP CONSTRAINT t_col_nn;
```

`NOT VALID`는 기존 행을 검사하지 않고 제약만 등록합니다. `VALIDATE`는 쓰기를 막지 않고 검사합니다. 검증된 제약이 있으면 `SET NOT NULL`은 전체 스캔을 건너뜁니다. 이 동작은 PostgreSQL 12부터 가능합니다.

## DBA에게 확인할 것

- 백필 배치 크기와 실행 시간대를 정하세요.
- 복제 지연(replica lag)을 감시하세요. 대량 UPDATE는 복제본을 뒤처지게 합니다.
- 마이그레이션 도구에 `lock_timeout`을 설정하세요. 락을 오래 못 잡으면 스스로 실패하고, 서비스를 막지 않습니다.

DBMS와 버전, 컬럼 기본값이 있는지 알려 주시면 백필 쿼리를 구체적으로 써 드릴 수 있습니다.
