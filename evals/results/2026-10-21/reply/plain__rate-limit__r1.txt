토큰 버킷은 검색 API에는 맞는 방법입니다. 하지만 로그인 API는 분당 100회 한도가 너무 높아서 별도 규칙이 필요합니다.

## 토큰 버킷의 원리
- 사용자마다 버킷(토큰을 담는 통)이 하나 있고, 토큰을 최대 100개 담습니다.
- 요청 하나가 토큰 하나를 꺼냅니다. 토큰이 없으면 요청을 거절합니다.
- 토큰은 초당 약 1.67개(100÷60)씩 다시 채워집니다.
- 버킷이 가득 차 있으면 한꺼번에 100회까지 보낼 수 있습니다. 그 뒤에는 채워지는 속도만큼만 보낼 수 있습니다.

따라서 순간 폭주(burst)를 허용하면서 평균은 분당 100회로 묶습니다. 폭주 폭을 줄이려면 버킷 크기를 10~20으로 낮추고 채우는 속도는 그대로 두세요.

## 검색 API
토큰 버킷이 적합합니다. 사용자가 검색어를 연달아 입력하는 패턴은 짧은 폭주이기 때문에, 이를 허용하는 방식이 사용 경험에 맞습니다.

고정 윈도우(1분 단위로 횟수를 세는 방식)는 피해야 합니다. 윈도우 경계에서 짧은 시간에 최대 200회가 통과할 수 있기 때문입니다.

## 로그인 API
- 로그인 전에는 사용자를 알 수 없습니다. 한도의 키를 IP와 시도한 계정 ID로 잡아야 합니다.
- 분당 100회는 비밀번호 대입 공격(brute force)을 막지 못합니다. 계정당 실패 5~10회를 15분 안에 허용하는 식으로 훨씬 낮은 한도를 따로 두어야 합니다.
- 한도를 넘으면 계정을 잠시 잠그거나 추가 인증(CAPTCHA 등)을 요구할 수 있습니다.

## 구현할 때 주의할 점
- 서버가 여러 대이면 Redis 같은 공유 저장소에 버킷 상태를 두어야 합니다.
- 토큰 읽기와 차감은 Lua 스크립트 하나로 처리해야 합니다. 나누면 동시 요청이 경쟁해서 한도를 넘습니다.
- 거절할 때는 HTTP 429 상태 코드와 `Retry-After` 헤더를 반환해야 합니다.
