백필(backfill)은 기존 행의 새 컬럼에 값을 채우는 작업입니다. 지금은 이 작업 없이 NOT NULL을 한 번에 걸었기 때문에 테이블 전체가 잠겼습니다. 아래는 PostgreSQL 기준이고, MySQL이면 도구와 문법이 다릅니다.

## 멈춘 이유

NOT NULL 컬럼은 모든 행에 값이 있어야 합니다. DB가 20GB를 다시 쓰거나 전부 검사하는 동안 테이블 잠금(lock)을 잡고, 그동안 읽기와 쓰기가 대기합니다.

## 지금 할 일

1. 마이그레이션 세션을 취소해 잠금을 푸세요. 롤백은 보통 몇 초에서 몇 분 걸립니다.
2. 취소 전에 `pg_stat_activity`에서 마이그레이션 세션의 `pid`를 확인하세요.
3. 아래 명령으로 취소하세요.

```sql
SELECT pg_cancel_backend(<pid>);
```

취소가 안 되면 `pg_terminate_backend(<pid>)`를 쓰세요. 이 명령은 연결을 강제로 끊기 때문에 DBA와 먼저 상의해야 합니다.

## 다시 적용하는 순서

1. 기본값이 상수이고 PostgreSQL이 11 이상이면 `ADD COLUMN ... NOT NULL DEFAULT <상수>`가 즉시 끝납니다. 이 경우 백필이 필요 없습니다.
2. 기본값을 계산해야 하면 NULL을 허용하는 컬럼을 먼저 추가하세요. 이 작업은 메타데이터만 바꾸기 때문에 빠릅니다.
3. 새로 쓰는 행이 값을 넣도록 애플리케이션을 먼저 배포하세요.
4. 기존 행을 배치(batch, 일정 개수씩 묶음)로 백필하세요. 한 번에 1만~10만 행씩 갱신하고, 배치마다 커밋하며 짧게 쉬어야 합니다.
5. `WHERE col IS NULL` 건수가 0인지 확인하세요.
6. 제약을 `NOT VALID`로 추가하세요. 이 상태에서는 새 쓰기만 검사하기 때문에 잠금이 짧습니다.
7. `VALIDATE CONSTRAINT`로 기존 행을 검사하세요. 이 단계는 읽기와 쓰기를 막지 않습니다.
8. PostgreSQL 12 이상이면 `SET NOT NULL`이 검증된 제약을 보고 전체 스캔을 건너뜁니다. 그 뒤에 임시 제약을 지우세요.

배치 백필 예시입니다. `id` 기준으로 범위를 나눠 반복 실행하세요.

```sql
UPDATE big_table
SET new_col = <값>
WHERE id >= :start AND id < :start + 50000
  AND new_col IS NULL;
```

제약 적용 예시입니다.

```sql
ALTER TABLE big_table
  ADD CONSTRAINT new_col_nn CHECK (new_col IS NOT NULL) NOT VALID;
ALTER TABLE big_table VALIDATE CONSTRAINT new_col_nn;
ALTER TABLE big_table ALTER COLUMN new_col SET NOT NULL;
ALTER TABLE big_table DROP CONSTRAINT new_col_nn;
```

## 주의

- 백필은 복제 지연(replication lag)과 디스크 쓰기량을 늘립니다. 복제 지연을 보면서 배치 크기를 조절해야 합니다.
- 긴 트랜잭션은 vacuum을 막기 때문에 배치마다 커밋해야 합니다.
- 각 `ALTER TABLE` 앞에 `SET lock_timeout = '3s';`를 두면 대기 중인 잠금이 서비스를 막기 전에 실패합니다.

DB 종류와 버전, 새 컬럼의 값을 어떻게 계산하는지 알려 주시면 이 순서에 맞춰 구체적인 스크립트를 쓸 수 있습니다.
