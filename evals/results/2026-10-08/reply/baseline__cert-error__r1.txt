## 무슨 일인가요

curl이 서버가 보낸 인증서의 **발급자(CA) 체인을 신뢰할 수 있는 루트까지 연결하지 못한다**는 뜻입니다. 인증서 자체가 만료됐다는 뜻이 아니라, 로컬의 CA 저장소에 그 체인을 검증할 루트(또는 중간) 인증서가 없다는 뜻입니다.

사내 API에서 흔한 원인은 다음과 같습니다.

1. **사내 사설 CA**로 서명된 인증서입니다. 공인 CA 번들에는 사내 루트 CA가 없습니다.
2. **서버가 중간 인증서를 빠뜨리고** leaf 인증서만 보내고 있습니다. 브라우저는 보완해서 통과시키지만 curl은 실패합니다.
3. **사내 프록시나 보안 장비(SSL 검사)**가 TLS를 가로채 자체 CA로 재서명합니다.
4. 사용하는 curl이나 OpenSSL이 가리키는 CA 번들이 오래됐거나 경로가 잘못됐습니다.

## 먼저 원인 확인

```bash
# 서버가 보내는 체인과 발급자 확인
openssl s_client -showcerts -connect api.example.internal:443 </dev/null 2>/dev/null | grep -E "s:|i:|Verify return"

# curl이 쓰는 CA 번들 경로 확인
curl -v https://api.example.internal 2>&1 | grep -i "CAfile"
```

- 체인에 인증서가 1개뿐이고 발급자가 중간 CA라면 **서버 설정 문제(2번)**입니다.
- 발급자가 사내 CA 이름이라면 **사내 CA 미신뢰(1번, 3번)**입니다.

## 해결 방법

**1. 사내 루트 CA를 지정합니다. (권장)**
IT/보안팀에서 사내 루트 CA 인증서(`.pem`/`.crt`)를 받아 사용합니다.

```bash
curl --cacert /path/to/corp-root-ca.pem https://api.example.internal
```

매번 지정하기 싫다면 환경변수를 설정합니다.

```bash
export CURL_CA_BUNDLE=/path/to/corp-root-ca.pem   # ~/.zshrc에 추가
```

**2. macOS 키체인에 신뢰 등록합니다.**
```bash
sudo security add-trusted-cert -d -r trustRoot \
  -k /Library/Keychains/System.keychain corp-root-ca.pem
```
Apple 서명 curl(`/usr/bin/curl`)은 키체인을 사용합니다. Homebrew curl은 자체 번들을 쓰므로 방법 1이 필요할 수 있습니다.

**3. 서버 쪽 문제라면** 서버 관리자에게 leaf 인증서 뒤에 중간 인증서를 이어 붙인 fullchain 인증서를 설정하도록 요청하세요.

**4. 임시 우회 (테스트 용도로만 쓰세요)**
```bash
curl -k https://api.example.internal
```
`-k`는 검증을 완전히 끄므로 중간자 공격에 무방비입니다. 스크립트나 운영 환경에는 쓰지 마세요.

확인 명령의 출력을 알려주시면 어느 경우인지 더 구체적으로 짚어드리겠습니다.
