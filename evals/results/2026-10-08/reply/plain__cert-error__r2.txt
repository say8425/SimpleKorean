curl이 서버 인증서에 서명한 인증 기관(CA, 인증서를 발급하고 서명하는 기관)을 신뢰 목록에서 찾지 못했다는 뜻입니다. 사내 API는 보통 사내 CA나 TLS 검사 프록시가 인증서를 발급합니다. 이 CA의 루트 인증서가 curl이 쓰는 CA 번들(신뢰하는 CA 인증서 모음)에 없으면 이 오류가 납니다. 서버가 중간 인증서를 보내지 않아도 같은 오류가 납니다.

원인을 먼저 확인하세요. 아래 명령으로 서버가 보내는 인증서 체인을 볼 수 있습니다. 호스트 이름은 실제 API 주소로 바꾸세요.

```
openssl s_client -connect api.example.internal:443 -showcerts
```

출력 끝의 "Verify return code"가 20이면 루트 CA를 모르는 것이고, 21이면 중간 인증서가 빠진 것입니다. 21이면 서버 관리자에게 체인 전체를 보내도록 요청해야 합니다.

20이면 보안팀이나 IT 문서에서 사내 루트 CA 인증서를 PEM 형식으로 받으세요. 그다음 curl에 파일을 지정하세요.

```
curl --cacert /path/to/company-root-ca.pem https://api.example.internal/health
```

매번 지정하기 번거로우면 셸 설정에 환경 변수를 추가하세요. 이 변수는 curl이 기본 CA 번들 대신 쓸 파일을 가리킵니다. 사내 CA만 담은 파일을 가리키면 공개 사이트 검증이 실패하므로, 기존 번들에 사내 CA를 이어 붙인 파일을 만들어 쓰세요.

```
export CURL_CA_BUNDLE=/path/to/combined-ca-bundle.pem
```

`-k`나 `--insecure`는 쓰지 마세요. 인증서 검증을 끄기 때문에 중간자 공격(통신 중간에서 내용을 가로채는 공격)에 노출됩니다. 임시 점검에서도 사내 토큰이나 개인정보를 보내면 안 됩니다.

회사 VPN이나 보안 프록시를 쓰는 중이면 `curl -v`의 출력에서 인증서 발급자(issuer)를 확인하세요. 발급자가 API 서버가 아니라 프록시 제품 이름이면, 해당 프록시의 루트 CA를 같은 방법으로 등록해야 합니다.
