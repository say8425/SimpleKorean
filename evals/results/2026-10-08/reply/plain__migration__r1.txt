백필(backfill)은 새 컬럼이 생기기 전부터 있던 기존 행에 값을 채우는 작업입니다. 마이그레이션이 멈춘 이유는 20GB 테이블의 모든 행을 한 번에 고치려 했기 때문입니다. 그동안 테이블 잠금(lock)이 유지되어 다른 쿼리도 대기합니다.

먼저 멈춘 마이그레이션을 취소하세요. 취소하면 롤백이 시작되고, 롤백 중에도 잠금이 남을 수 있습니다. 그러니 DBA와 함께 세션 상태를 확인하고 취소하세요.

그다음 NOT NULL 컬럼을 세 단계로 나눠 추가하세요. 1단계는 NULL을 허용하는 컬럼을 추가하는 것입니다. 이 작업은 테이블을 다시 쓰지 않아 빨리 끝납니다. 2단계는 기존 행을 작은 묶음(batch)으로 나눠 값을 채우는 것입니다. 3단계는 모든 행에 값이 생긴 뒤 NOT NULL 제약을 거는 것입니다. 아래는 PostgreSQL 12 이상 기준 예시입니다. 테이블명, 컬럼명, 값은 실제 이름으로 바꾸세요.

```sql
-- 1단계
ALTER TABLE orders ADD COLUMN status text;

-- 2단계: 끝나는 행이 0이 될 때까지 반복
UPDATE orders SET status = 'legacy'
WHERE id IN (
  SELECT id FROM orders WHERE status IS NULL LIMIT 10000
);

-- 3단계
ALTER TABLE orders ADD CONSTRAINT status_nn CHECK (status IS NOT NULL) NOT VALID;
ALTER TABLE orders VALIDATE CONSTRAINT status_nn;
ALTER TABLE orders ALTER COLUMN status SET NOT NULL;
ALTER TABLE orders DROP CONSTRAINT status_nn;
```

기본값이 모든 행에 같은 상수라면 더 간단합니다. PostgreSQL 11 이상에서는 `ADD COLUMN status text NOT NULL DEFAULT 'legacy'`가 테이블을 다시 쓰지 않고 바로 끝납니다. 기본값이 행마다 달라야 하면 위의 세 단계를 쓰세요.

2단계의 묶음 크기는 복제 지연(replication lag)과 부하를 보면서 조정하세요. 묶음이 너무 크면 잠금 시간이 길어지고, 복제본이 뒤처질 수 있습니다. MySQL을 쓰면 명령이 다릅니다. 이 경우 gh-ost나 pt-online-schema-change 같은 온라인 스키마 변경 도구를 DBA와 상의하세요.
