백필(backfill)은 이미 있는 행의 새 칼럼에 값을 채우는 작업입니다. NOT NULL 칼럼은 모든 행에 값이 있어야 하는데, 기본값 없이 추가하면 데이터베이스가 20GB 전체를 한 번에 처리하려 합니다. 이 동안 테이블 락(lock, 다른 쓰기를 막는 잠금)이 유지되어 마이그레이션이 멈추고, 같은 테이블을 쓰는 쿼리도 대기합니다.

해결은 세 단계로 나누는 것입니다. 먼저 멈춘 마이그레이션을 취소해야 합니다. 다음으로 칼럼을 NULL 허용으로 추가하고, 기존 행을 작은 배치(batch)로 나눠 채웁니다. 마지막으로 NOT NULL 제약을 겁니다. 배치마다 커밋해야 락이 짧게 유지되고 로그 부담도 줄어듭니다.

아래 SQL은 PostgreSQL 12 이상을 가정합니다. `orders`, `status`, 채울 값은 예시 이름이므로 실제 테이블에 맞게 바꿔야 합니다. MySQL이면 문법이 다릅니다.

```sql
-- 1. NULL 허용으로 추가 (보통 바로 끝남)
ALTER TABLE orders ADD COLUMN status text;

-- 2. 배치로 백필 (id 범위를 옮기며 끝날 때까지 반복, 배치마다 커밋)
UPDATE orders SET status = 'unknown'
WHERE id >= 1 AND id < 10001 AND status IS NULL;

-- 3. NOT NULL 적용 (검증을 미리 해 두면 전체 스캔 락을 피함)
ALTER TABLE orders ADD CONSTRAINT status_nn CHECK (status IS NOT NULL) NOT VALID;
ALTER TABLE orders VALIDATE CONSTRAINT status_nn;
ALTER TABLE orders ALTER COLUMN status SET NOT NULL;
ALTER TABLE orders DROP CONSTRAINT status_nn;
```

모든 행에 같은 상수를 넣는다면 백필이 필요 없을 수 있습니다. PostgreSQL 11 이상에서는 `ADD COLUMN status text NOT NULL DEFAULT 'unknown'`이 테이블을 다시 쓰지 않고 바로 끝납니다. 행마다 값이 달라서 다른 칼럼에서 계산해야 할 때만 위의 백필이 필요합니다.

애플리케이션이 새 칼럼에 값을 쓰도록 배포하는 일은 2단계 전에 끝내야 합니다. 그렇지 않으면 백필 중에 새 행이 NULL로 들어옵니다.
