백필(backfill)은 이미 있는 행의 새 컬럼에 값을 채우는 작업입니다. NOT NULL 컬럼은 모든 행에 값이 있어야 하기 때문에, 20GB 테이블에 한 번에 추가하면 테이블 전체를 다시 쓰다가 멈출 수 있습니다. 이때 락(lock, 다른 세션의 접근을 막는 잠금)이 길게 유지되어 같은 테이블을 읽고 쓰는 서비스 쿼리도 대기할 수 있습니다. 그래서 먼저 멈춘 마이그레이션을 취소해야 합니다. 서비스 쿼리가 이미 밀렸다면 취소 전에 DBA와 세션을 함께 확인해야 합니다.

해결 순서는 네 단계입니다. 먼저 NULL을 허용하는 컬럼으로 추가합니다. 이 변경은 메타데이터만 바꾸므로 거의 즉시 끝납니다. 다음으로 새 행에 값을 쓰도록 애플리케이션을 배포하고, 기존 행은 1만 건 안팎의 배치로 나눠 채웁니다. 마지막으로 NOT NULL 제약을 겁니다.

아래 예시는 PostgreSQL 12 이상을 가정합니다. 테이블, 컬럼, 기본값은 임의의 이름이므로 바꿔 쓰세요.

```sql
ALTER TABLE orders ADD COLUMN status text;

-- 백필: id 범위를 옮겨 가며 끝까지 반복
UPDATE orders SET status = 'legacy'
WHERE id BETWEEN 1 AND 10000 AND status IS NULL;

-- 백필이 끝난 뒤
ALTER TABLE orders ADD CONSTRAINT status_nn
  CHECK (status IS NOT NULL) NOT VALID;
ALTER TABLE orders VALIDATE CONSTRAINT status_nn;
ALTER TABLE orders ALTER COLUMN status SET NOT NULL;
ALTER TABLE orders DROP CONSTRAINT status_nn;
```

NOT VALID로 추가한 제약은 새 쓰기에만 먼저 적용됩니다. VALIDATE는 쓰기를 막지 않고 기존 행을 검사합니다. 검증된 제약이 있으면 SET NOT NULL이 전체 스캔을 건너뛰기 때문에 락이 짧게 끝납니다.

MySQL이면 절차가 다릅니다. 이 경우 gh-ost나 pt-online-schema-change 같은 온라인 변경 도구를 DBA와 함께 검토해야 합니다.
