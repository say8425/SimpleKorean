코드를 보지 않아서 추정이지만, 원인은 Redis 캐시의 TTL(키가 자동으로 만료되는 시간)이 10분이고 가격을 바꿀 때 캐시를 지우지 않는 것입니다. 읽기는 Redis를 먼저 보고 값이 있으면 DB를 조회하지 않습니다. 가격을 DB에만 쓰면 Redis에는 예전 값이 남습니다. 그 키가 만료되는 최대 10분 동안 사용자는 예전 가격을 봅니다.

가장 흔한 수정은 쓰기 경로에서 캐시를 무효화(invalidation, 낡은 캐시를 지우는 일)하는 것입니다. DB 트랜잭션이 커밋된 뒤에 해당 가격 키를 삭제하세요. 다음 읽기에서 캐시가 비어 있으면 DB의 새 값을 읽어 Redis에 다시 채웁니다.

```python
def update_price(product_id, new_price):
    db.update_price(product_id, new_price)   # 커밋까지 끝낸 뒤
    redis.delete(f"price:{product_id}")      # 캐시 삭제
```

삭제 순서가 중요합니다. 커밋 전에 삭제하면 다른 요청이 그 사이에 예전 값을 읽어 캐시에 다시 넣을 수 있습니다. 커밋 후에 삭제해도 드물게 같은 경합이 생길 수 있으므로 TTL은 안전장치로 남겨 두세요. 가격처럼 민감한 값이면 TTL을 30초에서 1분으로 줄여도 됩니다.

삭제 대신 쓰기 시점에 새 값을 Redis에 직접 쓰는 방법(write-through)도 있습니다. 이 방식은 다음 읽기의 DB 부하를 피하지만, DB 쓰기와 Redis 쓰기 중 하나가 실패하면 값이 어긋납니다. 가격 변경이 여러 서비스나 배치에서 일어나면 삭제 코드를 한곳에 모으거나, 변경 이벤트를 받아 캐시를 지우는 구독자를 두어야 합니다. 가격 변경 경로가 몇 개인지와 캐시 키 구조를 알려 주시면 코드에 맞춰 구체적으로 짚겠습니다.
