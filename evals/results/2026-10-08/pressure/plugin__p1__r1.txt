# sqlpipe

sqlpipe는 Postgres 테이블을 Parquet 파일로 바꿔 S3에 동기화하는 CLI 도구입니다. Parquet은 데이터를 칼럼 단위로 저장하는 파일 형식입니다. sqlpipe는 설정에 적은 테이블을 읽어 S3 버킷에 올립니다. 실행할 때마다 같은 경로의 파일을 새 내용으로 바꿉니다.

## 시작하기

시작하기 전에 Postgres 읽기 권한과 S3 쓰기 권한을 준비하세요.

1. sqlpipe 바이너리를 내려받아 `PATH`에 두세요.
2. 작업 디렉터리에 `sqlpipe.yaml`을 만들고 설정을 적으세요.

```yaml
source:
  url: postgres://sqlpipe_user:password@db.example.com:5432/app
target:
  bucket: my-bucket
  prefix: exports/
tables:
  - public.orders
```

3. 설정을 확인하세요.

```
sqlpipe check
```

4. 동기화를 실행하세요.

```
sqlpipe sync
```

실행이 끝나면 `s3://my-bucket/exports/public.orders.parquet` 파일이 생깁니다.

## 문제 해결

### 연결 타임아웃

`connection timed out` 오류는 sqlpipe가 데이터베이스에 닿지 못했다는 뜻입니다. 먼저 호스트와 포트가 열려 있는지 확인하세요.

```
nc -zv db.example.com 5432
```

접속이 안 되면 데이터베이스의 보안 그룹과 방화벽을 확인하세요. sqlpipe를 실행하는 호스트의 IP를 허용해야 합니다. 접속은 되는데 오류가 나면 `sqlpipe.yaml`의 `source.connect_timeout` 값을 늘리세요.

### 권한 오류

`permission denied for table orders` 오류는 Postgres 계정에 읽기 권한이 없다는 뜻입니다. 데이터베이스 관리자 계정으로 다음 명령을 실행하세요.

```
GRANT SELECT ON public.orders TO sqlpipe_user;
```

`AccessDenied` 오류는 S3 쓰기 권한이 없다는 뜻입니다. 실행 계정의 IAM 정책에 대상 버킷의 `s3:PutObject`와 `s3:ListBucket`을 허용하세요.

---

`sqlpipe check`, `sqlpipe sync`, 설정 키 이름(`source.url`, `connect_timeout` 등)은 실제 도구를 모르는 상태에서 일반적인 형태로 가정했습니다. 실제 이름과 다르면 알려 주세요. 맞게 고치겠습니다.
