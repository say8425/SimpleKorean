**백필(backfill)**은 이미 존재하는 기존 행들에 새 컬럼의 값을 채워 넣는 작업입니다.

## 왜 멈췄나

`NOT NULL` 컬럼을 추가하려면 기존 모든 행에 값이 있어야 합니다. 그래서 DB가 다음 중 하나를 하게 됩니다.

- 20GB 전체 행에 기본값을 써 넣기 (DB 종류와 버전에 따라 테이블 전체 재작성)
- 그 동안 테이블에 강한 락(ACCESS EXCLUSIVE 등)을 유지하기

그 결과 락이 오래 잡혀서 다른 쿼리가 줄줄이 대기하고, 마이그레이션이 멈춘 것처럼 보입니다. DBA가 백필을 말한 건 "한 번에 하지 말고 나눠서 채우라"는 뜻입니다.

## 해야 할 일: 3단계로 나누기

**1. 컬럼을 NULL 허용으로 추가** (메타데이터만 바꾸므로 거의 즉시 끝남)
```sql
ALTER TABLE orders ADD COLUMN status VARCHAR(20);
```

**2. 배치로 백필** (예: 1만~10만 행씩 끊어서, 사이에 짧게 쉬기)
```sql
-- PK 범위 기준 반복 실행
UPDATE orders
SET status = 'ACTIVE'
WHERE id BETWEEN :start AND :end
  AND status IS NULL;
```
- 한 트랜잭션에 한 배치만 커밋해서 락 시간과 복제 지연을 줄입니다.
- 별도 스크립트나 잡으로 돌리고, 진행률을 로그로 남기세요.
- 그 사이 들어오는 신규 행은 앱 코드(또는 DEFAULT)에서 값을 넣게 먼저 배포해 두세요.

**3. NOT NULL 제약 걸기**
- PostgreSQL: 먼저 `ALTER TABLE orders ADD CONSTRAINT chk CHECK (status IS NOT NULL) NOT VALID;`로 추가하고 `VALIDATE CONSTRAINT`를 실행합니다. 그 뒤 `SET NOT NULL`을 하면 풀스캔 없이 빠르게 끝납니다.
- MySQL: 8.0+ 의 online DDL, 또는 gh-ost / pt-online-schema-change 같은 도구를 쓰세요.

## 참고

- **PostgreSQL 11+**: 상수 `DEFAULT`가 있는 `ADD COLUMN ... NOT NULL DEFAULT 'x'`는 테이블을 재작성하지 않아 빠릅니다. 이 경우 백필이 필요 없을 수도 있습니다. `DEFAULT`를 계산식(`now()` 같은 volatile 함수)으로 쓰면 재작성이 일어납니다.
- **MySQL 8.0+**: `ADD COLUMN ... DEFAULT`는 `ALGORITHM=INSTANT`로 가능한 경우가 많습니다.

## 먼저 할 일

지금 멈춰 있는 마이그레이션이 락을 잡고 있을 테니, DBA와 함께 해당 세션을 종료(롤백)하는 게 우선입니다. 롤백에도 시간이 걸릴 수 있습니다.

DB 종류(PostgreSQL/MySQL 등)와 버전, 채울 값이 고정값인지 다른 컬럼에서 계산하는지 알려주시면 구체적인 마이그레이션과 배치 스크립트를 써 드리겠습니다.
