사내 API의 인증서를 발급한 CA(인증서 발급 기관)를 curl이 신뢰하지 못해서 나는 오류입니다. 사내 CA 인증서를 curl에 알려 주면 해결됩니다.

원인은 보통 세 가지입니다. 첫째, 사내 API가 사내 루트 CA로 서명한 인증서를 씁니다. 이 CA는 공개 신뢰 목록에 없습니다. 둘째, 서버가 중간 인증서를 보내지 않아서 인증서 체인이 끊깁니다. 셋째, 회사 프록시가 TLS 통신을 가로채고 자체 인증서를 다시 서명합니다.

먼저 서버가 보내는 체인을 확인하세요. `host`는 사내 API 호스트로 바꾸세요.

```
openssl s_client -connect host:443 -showcerts </dev/null
```

출력의 `Verify return code`와 `issuer`를 보면 원인을 구분할 수 있습니다. 발급자가 사내 CA 이름이면 첫째나 셋째 경우입니다. 체인에 서버 인증서 하나만 있으면 둘째 경우입니다.

첫째와 셋째 경우는 다음 순서로 고치세요.

1. 보안팀이나 IT 위키에서 사내 루트 CA 인증서(PEM 형식)를 받으세요.
2. 파일 경로를 `--cacert`로 지정해 요청하세요.
3. 매번 지정하기 싫으면 환경 변수 `CURL_CA_BUNDLE`에 그 경로를 설정하세요.

```
curl --cacert /path/to/company-root-ca.pem https://host/path
```

macOS 키체인에 사내 CA가 이미 있어도 Homebrew로 설치한 curl은 키체인을 읽지 않을 수 있습니다. 이때도 `--cacert`를 쓰세요.

둘째 경우는 서버 쪽 문제입니다. 서버 관리자에게 중간 인증서를 포함한 전체 체인(fullchain)을 배포하도록 요청하세요.

`curl -k`는 임시 확인용으로만 쓰세요. 이 옵션은 인증서 검증을 완전히 끄기 때문에 중간자 공격(통신 중간에서 내용을 가로채는 공격)에 노출됩니다. 스크립트나 운영 환경에는 넣으면 안 됩니다.
