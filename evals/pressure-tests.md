# 압력 시험

스킬의 행동을 확인하는 시나리오와 통과 기준입니다. 시나리오마다 스킬 없이 한 번, 플러그인을 켜고 한 번 실행해서 기준과 비교합니다. 기준선에서도 통과하는 기준은 아무것도 증명하지 못합니다. 쓸모 있는 기준은 기준선이 실패하는 기준입니다.

압력 시험은 레포지토리 최상위에서 `python3 evals/run_pressure.py --out evals/results/<날짜>/pressure`로 실행하세요. 이 스크립트는 `claude` CLI를 부릅니다. 출력 파일 이름은 `<조건>__p<번호>__r<회차>.txt`입니다. 조건은 `baseline`(스킬 없음)과 `plugin`(이 레포지토리를 `--plugin-dir`로 올림) 두 가지입니다.

두 조건 모두 설정과 MCP 서버를 읽지 않습니다. 기준선은 파일 도구를 쓰지 않습니다. 도구를 열어 둔 기준선이 디스크에서 이 레포지토리의 규칙 목록을 찾아 읽은 적이 있기 때문입니다. 플러그인 조건은 스킬 파일을 읽는 Read와 Skill만 씁니다. 디렉터리를 뒤지는 Glob과 Grep은 쓰지 않습니다.

기계로 셀 수 있는 기준은 시나리오마다 적은 린터 명령으로 확인하세요. 나머지 기준은 출력을 읽고 판정하세요.

## 시나리오 1: 자연스러운 문서 과제

> Postgres 테이블을 Parquet 파일로 S3에 동기화하는 CLI 도구 sqlpipe의 문서를 써 주세요. 소개, '시작하기' 절, 연결 타임아웃과 권한 오류를 다루는 '문제 해결' 절을 넣고 1,200자 안팎으로 써 주세요.

통과 기준:

- [ ] 절차문에 15어절을 넘는 문장이 없습니다.
- [ ] 설명문에 20어절을 넘는 문장이 없습니다.
- [ ] 짐작과 권고 표현이 없습니다.
- [ ] 확인하는 동작을 "확인하다" 하나로 씁니다.
- [ ] 조건이 모두 명령 앞에 옵니다.
- [ ] 코드, 플래그, 오류 문구를 바꾸지 않습니다.

기계 확인: `python3 evals/ko_lint.py --type procedural <파일>`에서 `sentence_over_limit`, `hedge`, `synonym_rotation`, `trailing_condition`이 0이어야 합니다.
